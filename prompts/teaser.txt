티저형 제안서의 목적:
- 아직 수요기업과 미팅 또는 깊은 관계가 형성되기 전, "이 기술이 귀사와 관련 있을 수 있다"는 관심을 만들기 위한 자료입니다.
- 기술이전 계약이나 기술료를 바로 요구하지 말고, 기술검토 미팅을 자연스럽게 요청하세요.
- 기술의 모든 내용을 설명하기보다, 수요기업의 현재 사업과 연결되는 접점, 검토할 만한 이유, 다음 미팅에서 확인할 질문을 짧고 선명하게 제시하세요.

티저형 제안서 원칙:
- A4 2~3페이지 분량 (섹션 4개)
- 수요기업을 "귀사"로 통일
- 기술 자랑 금지 - "귀사가 검토해볼 이유" 중심으로 서술
- 과장된 사업화 확정 표현 금지. "가능성", "검토", "적용 후보", "공동검토" 표현을 사용
- 원자료에서 확인되지 않은 매출 증가, 원가 절감률, 하중 감소율, 개발기간 단축, 시장점유율 등 정량 수치를 임의로 만들지 말 것
- 불확실한 사실은 "(추정)" 또는 "추가 확인 필요"로 표시
- 마지막은 반드시 기술검토 미팅 요청 CTA로 종료
- 작성 가이드 주석, 체크리스트는 출력에 포함하지 말 것

출력 형식: Markdown

Markdown 작성 규칙:
- 아래 섹션 제목과 순서를 반드시 유지할 것
- 제목은 #, ##만 사용할 것
- 표는 GitHub Flavored Markdown 표로 작성하고, 각 표의 열 수를 모든 행에서 동일하게 유지할 것
- 표 셀 안에는 줄바꿈, 목록, 파이프 문자(|), HTML 태그를 넣지 말 것
- 링크는 Markdown 링크 대신 "자료명 (URL)" 형태로 쓸 것
- 코드블록과 작성자 메모를 출력하지 말 것
